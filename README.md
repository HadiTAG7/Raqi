# راقي — متابعة الباقات والشرائح والفواتير

تطبيق ويب شخصي (مستخدم واحد) لتجميع كل ما يتعلق بباقات "راقي" في مكان واحد:

- **الباقات**: تاريخ تفعيل الخصم، نهاية الخصم، نهاية الكاش باك، مع حالة كل تاريخ (نشط / ينتهي قريباً / منتهي) والأيام المتبقية.
- **الشرائح**: كل باقة فيها 5 شرائح ثابتة (1 أساسي، 2 دولي، 2 محلي) لكل واحدة اسم المستخدم ورقم الجوال والرقم المرجعي ودورة الفاتورة (شهرية أو سنوية).
- **الفواتير**: شبكة فترات لكل شريحة من بداية الفوترة حتى اليوم؛ اضغط على الفترة لتبديلها بين مدفوعة وغير مدفوعة.
- **الرئيسية**: ملخص، التواريخ القادمة مرتبة بالأقرب، والشرائح التي لم تُدفع فواتيرها للفترة الحالية.
- **نسخة احتياطية** بصيغة JSON من `/api/export`.

الواجهة عربية بالكامل (RTL). على Vercel يحمي التطبيقَ **Vercel Authentication** فلا يفتحه إلا صاحب الحساب. كلمة المرور داخل التطبيق **اختيارية** وتُفعَّل بضبط المتغير `APP_PASSWORD`.

## التقنيات

Next.js 16 (App Router) · React 19 · Tailwind CSS 4 · Drizzle ORM · Turso (libSQL) · jose · Zod · Playwright

## التشغيل محلياً

```bash
npm install
cp .env.example .env.local      # اختياري: اضبط APP_PASSWORD و AUTH_SECRET لتفعيل صفحة الدخول
npm run db:migrate              # ينشئ قاعدة SQLite محلية في data/local.db
npm run dev                     # http://localhost:3000
```

لتوليد `AUTH_SECRET` عشوائي (مطلوب فقط مع `APP_PASSWORD`):

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

## النشر على Vercel

الإعداد المعتمد لهذا المشروع:

| البند | القيمة |
|---|---|
| فرع الإنتاج | `main` (كل دفع إليه يُنشر تلقائياً) |
| منطقة الدوال | مومباي `bom1`، مثبّتة في `vercel.json` (أقرب منطقة متاحة للرياض) |
| قاعدة البيانات | Turso Cloud (الخطة المجانية) في مومباي `bom1`، مربوطة ببيئة **Production فقط** |
| الحماية | **Vercel Authentication** بنطاق **All Deployments**: لا يفتح التطبيق إلا صاحب حساب Vercel بعد تسجيل دخوله |
| Node.js | `22.x` (من `engines` في `package.json`) |

رابط التطبيق لا يُكتب في هذا المستودع لأنه عام. تجده في لوحة Vercel: المشروع ← **Domains**.

### إعداد مشروع جديد من الصفر

1. **استيراد المستودع**: من [vercel.com](https://vercel.com) ← **Add New → Project** ← اختر المستودع. يُكتشف Next.js تلقائياً، وفرع الإنتاج يجب أن يكون `main`.
2. **الحماية قبل أي بيانات**: **Settings → Deployment Protection** ← فعّل **Vercel Authentication** واختر **All Deployments** ← **Save**.
   - الخيار الافتراضي (Standard Protection) يحمي روابط المعاينة فقط ويترك رابط الإنتاج مفتوحاً.
3. **قاعدة البيانات**: **Storage → Create Database → Turso Cloud** ← الخطة **Free** ← المنطقة **bom1 (Mumbai)** ← **Create** ← **Connect Project** ← اترك Custom Prefix فارغاً ← فعّل **Production فقط** ← **Connect**.
   - منطقة القاعدة لا يمكن تغييرها بعد الإنشاء.
   - ربط Preview يجعل كل فرع تجريبي يشغّل الهجرات على قاعدة الإنتاج نفسها، لذلك لا تربطه.
   - يضيف التكامل `TURSO_DATABASE_URL` و`TURSO_AUTH_TOKEN` تلقائياً.
4. **النشر**: إن كان هناك نشر سابق قبل ربط القاعدة فاعمل **Redeploy** من **Deployments**، لأن المتغيرات الجديدة لا تصل للنشر القائم. أثناء البناء يطبّق `scripts/migrate.mjs` الهجرات على Turso.

### كلمة مرور داخل التطبيق (اختياري)

الحماية الأساسية هي Vercel Authentication. إن أردت إضافة كلمة مرور خاصة بالتطبيق أيضاً: أضف `APP_PASSWORD` و`AUTH_SECRET` (32 حرفاً أو أكثر) في **Settings → Environment Variables** لبيئة Production ثم **Redeploy**. بدونهما لا تظهر صفحة الدخول.

### متغيرات البيئة

| المتغير | مطلوب | الوصف |
|---|---|---|
| `APP_PASSWORD` | لا | كلمة مرور الدخول. ضبطها يفعّل صفحة الدخول؛ تركها فارغة يترك التطبيق مفتوحاً |
| `AUTH_SECRET` | مع `APP_PASSWORD` | سر توقيع كوكي الجلسة (32+ حرفاً). تغييره يُسجّل الخروج من كل الأجهزة |
| `TURSO_DATABASE_URL` | في الإنتاج | يضيفه تكامل Turso. محلياً يمكن تركه فارغاً فيُستخدم `file:./data/local.db` |
| `TURSO_AUTH_TOKEN` | في الإنتاج | يضيفه تكامل Turso |

## النسخة الاحتياطية

زر **نسخة احتياطية** في الشريط العلوي (أو `/api/export`) يحمّل ملف JSON يحوي كل الباقات والشرائح والمدفوعات.

## بنية المشروع

```
src/
├─ proxy.ts                 بوابة المصادقة (كل المسارات ما عدا /login)
├─ app/
│  ├─ login/                صفحة الدخول
│  ├─ (app)/                المنطقة المحمية: الرئيسية، الباقات، التعديل
│  └─ api/export/           النسخة الاحتياطية
├─ actions/                 Server Actions (الدخول، الباقات، الشرائح، الدفع)
├─ db/                      المخطط، العميل، الاستعلامات، التعديلات
├─ lib/                     التواريخ، الفترات، الفوترة، التحقق، النصوص العربية
└─ components/              مكونات الواجهة
drizzle/                    ملفات الهجرة المولّدة
scripts/migrate.mjs         تطبيق الهجرات (يعمل وقت البناء على Vercel)
tests/                      اختبارات الوحدة والمتصفح
```

## تعديل المخطط

بعد تعديل `src/db/schema.ts`:

```bash
npm run db:generate   # يولّد ملف هجرة جديد في drizzle/
npm run db:migrate    # يطبّقه محلياً
```

ارفع ملفات `drizzle/` مع الكود؛ ستُطبَّق تلقائياً عند البناء التالي على Vercel.
